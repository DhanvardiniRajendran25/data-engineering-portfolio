Stage Breakdown

What happens at each step

Ingest — SEC EDGAR

SEC EDGAR bulk downloader fetches financial filings (10-K annual reports, 10-Q quarterly reports, 8-K current reports). Filing metadata is stored alongside the document for traceability. DVC tracks this stage as a pipeline input with a content hash — re-download only triggers if the source changes.

Detection — Detectron2

Detectron2 object detection model runs on document page images to identify table region bounding boxes. It also classifies other layout regions: title, section header, body text, figure, caption. This spatial map is passed to LayoutLMv3 so it knows exactly where to find table content.

Parsing — LayoutLMv3

LayoutLMv3 is a multimodal transformer that understands text and layout jointly. It handles the hardest table structures: multi-column layouts, merged cells, row/column span attributes, and nested sub-tables. Neither a pure text extractor nor a pure vision model can do this alone.

Export — Docling

Docling converts the parsed table structure into three formats: JSON for programmatic access, Markdown for LLM consumption (tables as pipe-delimited strings), and CSV per table for analytics. Each table is exported as a separate file with its filing ID and page number as metadata.

Key Decisions

Why it was built this way

Decision 1

DVC pipeline management for reproducibility. Financial document processing is long-running and expensive. DVC tracks each stage's inputs and outputs with content hashes, so changing the LayoutLMv3 model version reruns only the parsing and export stages — not the download or detection stages. This also makes the pipeline auditable: any output can be traced to the exact model version and inputs that produced it.

Decision 2

Detectron2 + LayoutLMv3 together, not separately. Detectron2 is excellent at finding where tables are (spatial detection) but knows nothing about cell content. LayoutLMv3 understands table structure deeply but needs spatial coordinates as input. Neither alone produces an accurate parse. The two-stage approach combines spatial detection with structural understanding.

Decision 3

Three output formats instead of one. SEC EDGAR data has three primary downstream consumers: downstream Python code needs JSON, LLM summarization workflows need Markdown (pipe-delimited tables are the standard LLM format), and analyst teams need CSV. Generating all three at export time costs negligible extra compute versus the detection and parsing stages.
