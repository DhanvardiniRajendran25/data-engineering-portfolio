Stage Breakdown

What happens at each step

Source & Profile

IMDb distributes 7 TSV files: title.basics, title.akas, title.principals (91M+ rows), title.crew, title.episode, title.ratings, name.basics. Python ydata-profiling and Alteryx surface column nullability, value distributions, and IMDb-specific encoding quirks before any SQL is written.

NULL Normalization

IMDb encodes missing values as the literal string \N — not SQL NULL. Every pipeline that treats \N as a value will produce incorrect aggregations and broken JOINs. A preprocessing step replaces all \N occurrences with proper SQL NULLs before staging.

Parallel ADF Ingestion

ADF orchestrates 7 Copy Activities in parallel — one per dataset — each loading into its own Snowflake staging table. Schema validation is applied on ingest. Parallel execution cuts total wall-clock load time by approximately 70% vs sequential.

Staging → Curated

Staging tables preserve raw data exactly as loaded (minus NULLs). The curated analytics layer adds join-optimized views across datasets: genre-decade performance grids, director filmography aggregates, title cross-reference tables — all Power BI-ready.

Key Decisions

Why it was built this way

Decision 1

\N → NULL normalization before any SQL. IMDb uses the literal string \N as their missing-value placeholder. If this isn't caught at ingest, every COUNT(), AVG(), and JOIN on NULL-intended columns returns wrong results silently — one of the hardest classes of data quality bugs to find after the fact.

Decision 2

Parallel ADF dataset loads. All 7 IMDb datasets are independent of each other at ingest time — no cross-dataset foreign key enforcement happens at the load stage. Running them in parallel via ADF ForEach with concurrent Copy Activities eliminates the serial bottleneck and scales naturally when IMDb releases updated dumps.

Decision 3

Staging-then-curate pattern. Keeping raw (NULL-normalized) data in staging means any curated view can be rebuilt from scratch by replaying the staging → curate transformation. If a business logic change is needed, no re-ingestion is required — just recompute the curated layer. Raw data stays immutable and auditable.
